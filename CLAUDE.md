# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**Drukspil** is a free Danish drinking-game web app for the owner and their friends, built to replace paid apps (40–70 kr/month). One phone is passed around the table. Games: Imposter (word pairs, say one word each) and Bombe (categories and "scenarier", no letter mode). Hitster (songs over Spotify) is the third, with three modes the owner's group actually plays: Klassisk (place the song in your year timeline), Kasser (guess title, artist and year; the opponent holds the phone and ticks three boxes, one point each) Klip (hear 1, 5, 15, 30 seconds; faster guess gives more points: 4, 3, 2, 1) and Streams (higher or lower on Spotify stream counts; the only mode that also runs without a Spotify login, just without music). A Spyfall-style "Spygame" was tried and parked in `_backup-v1/spygame/`; the owner wants to revisit it later, not now. The owner is a group of 21-year-old guys: content must be fun, competitive and talk-driven, not "point at each other and giggle" decks (those were removed on purpose). See `README.md` for rules, structure and how to run it.

## Tech

Vanilla HTML/CSS/JS, no build step, no framework, no backend. Serve the folder statically (`start.bat`, port 3002). Installable PWA (`manifest.webmanifest`, `sw.js`), works offline after first load.

## Architecture

- `app.js`: core (`App`). Navigation, player list, settings, `localStorage`, Web Audio sounds, vibration, wake lock, UI building blocks (`App.ui.shell/toggle/seg/stepper/range`).
- `games/*.js`: one file per game. Each calls `App.register({ id, navn, kort, farve, render, onEnter, onLeave })` and registers button handlers with `App.on('name', fn)`. Buttons in HTML use `data-action="name"`; toggles use `data-change`, sliders `data-input`, forms `data-form`. Per-game settings persist via `App.gameSettings(id, defaults)`.
- `spotify.js` (`Spotify`): used only by Hitster. Authorization Code with PKCE (no secret; the public Client ID is in the file), token refresh, devices, play/pause via the Web API, and `findTrack` (searches title and artist, picks the original by album year, caches in `localStorage`). The app does not play audio itself, it remote-controls a Spotify Connect device. Spotify Development Mode (Feb 2026 rules): owner needs Premium, max 5 users, search `limit` max 10, batch endpoints gone, redirect URI must be `https://` or `http://127.0.0.1:PORT` (never `localhost`), so `start.bat` opens 127.0.0.1. `Spotify.blocked()` detects unusable origins. The login redirect returns to the page URL with `?code=`, handled in `games/hitster.js` on `DOMContentLoaded`; `sw.js` skips such requests. Hitster persists the running game in `localStorage` (`drukspil.hitster.run`) because the browser can be killed while the Spotify app is in front. In `games/hitster.js` the mode lives in `S.mode`/`H.mode` and the phases are `turn`, `place` (Klassisk), `judge` (Kasser), `clip`/`who` (Klip), `hl` (Streams; guess and result share the screen, `H.res` decides which), `reveal`, `win`/`end`. The Spotify Web API has no stream counts (and Development Mode dropped `popularity`), so `data/hitster-streams.js` is a generated snapshot in millions keyed by `'Titel|Kunstner'`; regenerate it with `node tools/update-streams.js` (scrapes kworb.net's top 2500, songs below that are simply left out of Streams), never edit it by hand or fill in numbers from memory. Countdown timers update the `.timer` element directly on each tick instead of re-rendering. Klip stops the song with a `setTimeout` after `Spotify.play` resolves, so real clip length depends on Spotify latency; `S.lag` (ms, "Justér klip") compensates. No "+" slot is shown between two timeline cards with the same year (the owner found it cluttered, and either side is correct).
- `data/*.js`: all content. `hitster-songs.js` holds `['Titel', 'Kunstner', år]` rows (year = original release year, which is what the game scores on, not Spotify's album date). Imposter word pairs (`[ord, lignende ord]`) per category, Bombe categories ("nævn ting") and scenarios ("Ting man siger, når...": funny situations a 21-year-old relates to; these are the good part). Adult content lives in separate `*_ADULT` arrays / `adult: true` categories and is only shown when the "Frækt indhold" toggle is on.
- `style.css`: chunky game look, mobile-first. The owner liked the Clash Royale-style buttons and cards but not the royal-blue diamond background, so the page is now deep plum (`--bg`) with a warm glow at the top, a blue glow at the bottom and faint bubble rings in several tile sizes; panels are indigo (`--panel`), bars use `rgba(var(--bar), a)`. Chunky buttons with dark outline and pressed bottom edge, display font Lilita One (self-hosted in `fonts/`) with text outline via the `--o-xs/--o-s/--o-l` text-shadow variables. Button colours are semantic (gold primary, blue secondary, green confirm, red remove); the game's own colour goes in `--accent` on `.screen`, its home tile and card frames. Cream "paper" cards (`.reveal-box`, `.deck-card`) use dark text. Entry animations only run when a tap re-renders (`#app.anim`), never on timer ticks; games can force them with `App.render(true)`.
- Icons are inline SVG, 64x64, dark `#0d1b3e` outline, drawn in code (no image files). Shared ones live in `App.icons`; each game passes its own as `ikon` to `App.register`. `App.ui.avatar(name, xl)` gives the coloured initial badge.

Load order in `index.html`: data files, `app.js`, `spotify.js`, then `games/*.js`, then `App.init()`.

## Conventions

- All user-facing text is Danish. Tone: playful party language, direct, short sentences. No em-dashes (use comma, colon or full stop). No emojis; use CSS or SVG for visuals.
- Keep play screens to one glance: big text, one primary button at the bottom, no scrolling mid-game.
- Drinks are phrased as "slurke" (sips) or "bunder"; keep penalties light and optional in spirit.
- When adding a game: new file in `games/`, register it (with an `ikon`), add it to `index.html` and to the precache list in `sw.js`.
- Privacy on pass-the-phone screens: the imposter's card must look identical in shape and colour to a normal word card from across the table; only the text differs.
- After editing JS/CSS: bump `?v=N` on every script/style tag in `index.html` and `CACHE`/`V` in `sw.js`, otherwise phones keep the old version.

## Testing

No test framework. Sanity-check with `node --check` on every JS file and click through the games in a mobile-sized browser (`.claude/launch.json` starts a local server on port 3002 for the in-app browser preview) (add players, run a full Imposter round, let a Bombe round explode in both Kategori and Scenarie mode). Hitster needs a real Spotify login that an agent must not do, so test it in the browser by faking Spotify: set `localStorage['drukspil.spotify.token']` to a non-expired fake token, then overwrite `Spotify.devices`, `.play`, `.pause`, `.findTrack` from the page console and play a round (the running game, including the hidden card, is readable in `localStorage['drukspil.hitster.run']`). Open the app on `http://127.0.0.1:3002`, not `localhost`.
