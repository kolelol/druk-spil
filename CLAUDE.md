# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**Drukspil** is a free Danish drinking-game web app for the owner and their friends, built to replace paid apps (40–70 kr/month). One phone is passed around the table. Games: Imposter (the plain version everyone knows: same word for all, the imposter gets nothing, one vote, one guess; no settings, the owner asked for exactly that on 2026-10-07), Bombe (235 categories copied, translated, from the classic categories-game list (Scattergories / Stop the bus, eslvault.com) and the 5 Second Rule cards; after several rounds of my own invented lists being called "mærkelige" and "elendig", the owner said on 2026-10-11 "søg på nettet og tag andres og kopier det", so never invent Bombe categories again, copy from known games; grouped in themes the game rotates so two of a kind never come in a row; keep Danish ones to a handful; minimum taps: opening the game starts a round at once, nothing to tap while it ticks, and tapping anywhere on the explosion starts the next round, settings sit behind a link there; the bomb sways, smokes and heats up the screen, and the explosion has a flash, shockwave, shards and embers) and Spygame (Spyfall-style: same word for all, the spy only knows the category; questions round the table on a single screen (no per-question taps), then a vote; settings folded away behind a summary line). Hitster (songs over Spotify) is the fourth, with three modes the owner's group actually plays: Klassisk (place the song in your year timeline), Kasser (guess title, artist and year; the opponent holds the phone and ticks three boxes, one point each) Klip (hear 1, 5, 15, 30 seconds; faster guess gives more points: 4, 3, 2, 1) and Streams (higher or lower on Spotify stream counts; the only mode that also runs without a Spotify login, just without music). A copy of the first Spygame still sits in `_backup-v1/spygame/`. The owner is a group of 21-year-old guys: content must be fun, competitive and talk-driven, not "point at each other and giggle" decks (those were removed on purpose). See `README.md` for rules, structure and how to run it.

## Tech

Vanilla HTML/CSS/JS, no build step, no framework, no backend. Serve the folder statically (`start.bat`, port 3002). Installable PWA (`manifest.webmanifest`, `sw.js`), works offline after first load.

## Architecture

- Seating (in `app.js`): the player list order IS the seating order round the table; the "Bordplan" screen (`seats`) lets the group tap names in the order they sit. `App.holder()`/`setHolder()` track who has the phone (not persisted), `App.fromHolder()` returns the seats rotated to start there, and `App.ui.table(names, { cur, done, start, pick, empty, sm })` draws the oval table (seat 0 at the bottom, then clockwise). Imposter and Spygame reveal in that order, start the next round at the last revealer, and let the first pass screen re-pick the holder by tapping a seat. The owner asked for this after a 10-player night where the phone kept crossing the table.
- `app.js`: core (`App`). Navigation, player list, settings, `localStorage`, Web Audio sounds, vibration, wake lock, UI building blocks (`App.ui.shell/toggle/seg/stepper/range`).
- `games/*.js`: one file per game. Each calls `App.register({ id, navn, kort, farve, render, onEnter, onLeave })` and registers button handlers with `App.on('name', fn)`. Buttons in HTML use `data-action="name"`; toggles use `data-change`, sliders `data-input`, forms `data-form`. Per-game settings persist via `App.gameSettings(id, defaults)`.
- `spotify.js` (`Spotify`): used only by Hitster. Authorization Code with PKCE (no secret; the public Client ID is in the file), token refresh, devices, play/pause via the Web API, and `findTrack` (searches title and artist, picks the original by album year, caches in `localStorage`). The app does not play audio itself, it remote-controls a Spotify Connect device. iOS suspends a paused Spotify app within minutes and the Connect device vanishes (the owner hit this: "det skal spille på Spotify, før man kan spille"), so inside a game Hitster never pauses: `hush()` in `games/hitster.js` plays a silent track (`Spotify.silence()` finds one by search and caches its URI in `localStorage`, falling back to a real pause) and `resumePlayback()` replays the song from the elapsed position; `pauseQuiet()` (a real pause) is only used when leaving Hitster. Spotify Development Mode (Feb 2026 rules): owner needs Premium, max 5 users, search `limit` max 10, batch endpoints gone, redirect URI must be `https://` or `http://127.0.0.1:PORT` (never `localhost`), so `start.bat` opens 127.0.0.1. `Spotify.blocked()` detects unusable origins. The login redirect returns to the page URL with `?code=`, handled in `games/hitster.js` on `DOMContentLoaded`; `sw.js` skips such requests. Hitster persists the running game in `localStorage` (`drukspil.hitster.run`) because the browser can be killed while the Spotify app is in front. In `games/hitster.js` the mode lives in `S.mode`/`H.mode` and the phases are `turn`, `place` (Klassisk), `judge` (Kasser), `clip`/`who` (Klip), `hl` (Streams; guess and result share the screen, `H.res` decides which), `reveal`, `win`/`end`. The Spotify Web API has no stream counts (and Development Mode dropped `popularity`), so `data/hitster-streams.js` is a generated snapshot in millions keyed by `'Titel|Kunstner'`; regenerate it with `node tools/update-streams.js` (kworb.net: first the global top 2500, then each artist's own page, found through the Spotify artist IDs cached in `tools/artist-ids.json`; kworb has no page for many smaller Danish acts, so about half the Danish songs have no number and are left out of Streams), never edit it by hand or fill in numbers from memory. Values under 100 million keep one decimal. Streams difficulty (`S.diff`: `let`, `mellem`, `svaer`) limits how far apart the two songs' counts may be (`BAND` in `drawChallenger`), and `S.htimer` gives an optional answer timer shown in the badge between the two cards. Countdown timers update the `.timer` element directly on each tick instead of re-rendering. Klip stops the song with a `setTimeout` after `Spotify.play` resolves, so real clip length depends on Spotify latency; `S.lag` (ms, "Justér klip") compensates. No "+" slot is shown between two timeline cards with the same year (the owner found it cluttered, and either side is correct).
- Bombe (`games/bombe.js`): the armed screen gets the classes `armed heat1..3` on `.screen` as the fuse burns (`heatClass(burnt())`, set on every tick in `flash()`), which CSS turns into faster sway, more smoke and a red glow; the boom screen builds its shards and embers with random inline `--x/--y/--dx/--dy` custom properties, and all explosion motion is CSS keyframes under `.screen.boom`. Role cards in Imposter and Spygame use `.reveal-box.same` (fixed min-height) so the imposter's card is the same size as a word card.
- `data/*.js`: all content. `hitster-songs.js` holds `['Titel', 'Kunstner', år]` rows (year = original release year, which is what the game scores on, not Spotify's album date). `HITSTER_SONGS_DK` (562 Danish songs, explicit ones included on purpose, chosen with `S.musik`: `alle`, `dk`, `int`; in `alle` the deck is balanced by `balance()` to as many Danish as international songs) was built by looking up each year in MusicBrainz, Deezer and iTunes and keeping a song only when two sources agreed; for old Danish music every single source is often wrong (reissue years, placeholder years), so never add years from memory or from one source. Imposter words are plain strings per category (600+ concrete nouns, each rated 1-5 for fun (sjov) and ease of hinting (nem) by five personas on 2026-10-11, scores in `tools/imposter-vurdering.json`; words under nem 3 or sjov 2.6, or rated 2 or lower by three of five, were removed, typical failures being too broad or dull everyday things (Stol, Dør, Gaffel), things the group does not know (Bridgerton, Lionel Richie, Lucky Luke) and near-duplicates (Pædagogmedhjælper next to Pædagog); rate new words the same way before adding them; modelled on the lists the popular Imposter apps use; the owner called the old abstract pairs "ubeskriveligt dårlige" and asked for lists from the internet rather than invented ones; keep Danish names and places to the most famous few, the owner found it "for meget dansk"), Bombe categories: `BOMBE_CATEGORIES` is an array of `{ tema, ord }` groups and `newPrompt()` in `games/bombe.js` never picks the same `tema` twice in a row; the lists are copies of known category games, not inventions, plus byen/druk/frækt, and only a handful of Danish ones. Rejected by the owner: open or "creative" prompts ("Måder at...", "Ting man kan tage et shot af"), attribute lists that need thinking ("Ting der er klistrede", "Dyr der lægger æg"), narrow trivia ("Spillere der har vundet Ballon d'Or", "Film med Leonardo DiCaprio") and school-book lists (Hovedstæder). Speed is the fun; do not add anything that makes people pause. Spygame words per category in `spygame-words.js` (830, rated by the same five personas on 2026-10-12, scores in `tools/spygame-vurdering.json`, kept only with sjov 3+ and nem 3+; out went small Danish clubs, half-forgotten players, Danish drama series and odd "Måder at dø på"). Bombe categories were rated the same way (`tools/bombe-vurdering.json`): kept if sjov 3+ and nem 3+, or nem 4.2+ since speed is what makes Bombe fun; the persona Emil does not follow football, so do not cut football categories on his score alone. Imposter was tightened the same day to sjov 3+ (501 words). On 2026-10-13 the owner called the remaining invented content "cringe" and "boomer-agtigt" ("Grunde til at skåle", the "Måder at dø på" quips) and asked that nothing be added that I think young people find cool. So the rule for all three games is: only real names and things; no invented situations ("Bestille en Uber til 300 meter"), stereotype jokes ("Lugt af Axe"), quips ("Pizza klokken 4") or slang an outsider thinks is youthful ("Fuckboy", "Netflix og chill", "Walk of shame"). The Spygame categories Byturen, Måder at dø på and Drengelejligheden were removed for that reason. The persona reviews cannot catch this kind of cringe, because the personas are written by the same model that wrote the content (they gave "McDonald's klokken 4" 5/5), so never use them to justify keeping invented phrases. Adult content lives in separate `*_ADULT` arrays / `adult: true` categories and is only shown when the "Frækt indhold" toggle is on.
- `style.css`: chunky game look, mobile-first. The owner liked the Clash Royale-style buttons and cards but not the royal-blue diamond background, so the page is now deep plum (`--bg`) with a warm glow at the top, a blue glow at the bottom and faint bubble rings in several tile sizes; panels are indigo (`--panel`), bars use `rgba(var(--bar), a)`. Chunky buttons with dark outline and pressed bottom edge, display font Lilita One (self-hosted in `fonts/`) with text outline via the `--o-xs/--o-s/--o-l` text-shadow variables. Button colours are semantic (gold primary, blue secondary, green confirm, red remove); the game's own colour goes in `--accent` on `.screen`, its home tile and card frames. Cream "paper" cards (`.reveal-box`, `.deck-card`) use dark text. Entry animations only run when a tap re-renders (`#app.anim`), never on timer ticks; games can force them with `App.render(true)`.
- Icons are inline SVG, 64x64, dark `#0d1b3e` outline, drawn in code (no image files). Shared ones live in `App.icons`; each game passes its own as `ikon` to `App.register`. `App.ui.avatar(name, xl)` gives the coloured initial badge.

Load order in `index.html`: data files, `app.js`, `spotify.js`, then `games/*.js`, then `App.init()`.

## Conventions

- All user-facing text is Danish. Tone: playful party language, direct, short sentences. No em-dashes (use comma, colon or full stop). No emojis; use CSS or SVG for visuals.
- Keep play screens to one glance: big text, one primary button at the bottom, no scrolling mid-game.
- Drinks are phrased as "slurke" (sips) or "bunder"; keep penalties light and optional in spirit.
- When adding a game: new file in `games/`, register it (with an `ikon`), add it to `index.html` and to the precache list in `sw.js`.
- Privacy on pass-the-phone screens: the imposter's card must look identical in shape and colour to a normal word card from across the table; only the text differs.
- After editing JS/CSS: bump `?v=N` on every script/style tag in `index.html` and `CACHE`/`V` in `sw.js`, otherwise phones keep the old version.

## Testing

No test framework. Sanity-check with `node --check` on every JS file and click through the games in a mobile-sized browser (`.claude/launch.json` starts a local server on port 3002 for the in-app browser preview) (add players, run a full Imposter round, let a Bombe round explode, run a Spygame round). Hitster needs a real Spotify login that an agent must not do, so test it in the browser by faking Spotify: set `localStorage['drukspil.spotify.token']` to a non-expired fake token, then overwrite `Spotify.devices`, `.play`, `.pause`, `.findTrack` from the page console and play a round (the running game, including the hidden card, is readable in `localStorage['drukspil.hitster.run']`). Open the app on `http://127.0.0.1:3002`, not `localhost`. CSS animations in the browser pane only advance while the pane is visible (a screenshot makes it visible), so `getAnimations()` reporting `currentTime 0` is the test environment, not a bug.
