# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

**Drukspil** is a free Danish drinking-game web app for the owner and their friends, built to replace paid apps (40–70 kr/month). One phone is passed around the table. Games: Imposter (the plain version everyone knows: same word for all, the imposter gets nothing, one vote, one guess; no settings, the owner asked for exactly that on 2026-10-07), Bombe (235 categories copied, translated, from the classic categories-game list (Scattergories / Stop the bus, eslvault.com) and the 5 Second Rule cards; after several rounds of my own invented lists being called "mærkelige" and "elendig", the owner said on 2026-10-11 "søg på nettet og tag andres og kopier det", so never invent Bombe categories again, copy from known games; grouped in themes the game rotates so two of a kind never come in a row; keep Danish ones to a handful; minimum taps: opening the game starts a round at once, nothing to tap while it ticks, and tapping anywhere on the explosion starts the next round, settings sit behind a link there; the bomb sways, smokes and heats up the screen, and the explosion has a flash, shockwave, shards and embers) and Spygame (Spyfall-style: same word for all, the spy only knows the category; questions round the table on a single screen (no per-question taps), then a vote; settings folded away behind a summary line). Hitster (songs over Spotify) is the fourth, with three modes the owner's group actually plays: Klassisk (place the song in your year timeline), Kasser (guess title, artist and year; the opponent holds the phone and ticks three boxes, one point each) Klip (rebuilt on 2026-10-16 after the owner pointed at Songless (playdaily.org/songless) and Songspot (songspot.net) and said "som dette bare bedre og pænere": each player gets their own song in turn, hears 0.5 s first, and guesses by searching for the title. The score is time, not points: Skip or a wrong guess pushes the "wall" one step out (`WALLS`: 0.5, 1, 1.5, 2, 3, 4, 5, 7, 10, 15, 20, 30 s) and the song keeps playing from where it is instead of restarting ("en mur der bliver skubbet i stedet for fuld reset"); a guess counts the wall it was made at, a miss counts `MISS` (40 s), lowest total time wins. Five difficulties (`S.kdiff`: let, mellem, svaer, ekspert, umulig) pick a fifth of the songs by stream count in `kpool()`, Danish and international split separately so the Danish ones do not all land in Umulig) and Streams (higher or lower on Spotify stream counts; the only mode that also runs without a Spotify login, just without music). Streams and Klip can also be played alone ("Alene", `S.solo`, asked for on 2026-10-16 so one can "tracke sin rekord og slå den"): Streams runs until the first wrong answer and the record is the longest streak; Klip is always `SOLO_SONGS` (10) songs and the record is the lowest total time. Records live in `S.rec` keyed by the settings that change difficulty (`recKey()`), so each combination has its own, and the end screen `renderSoloEnd` shows "Ny rekord!". A copy of the first Spygame still sits in `_backup-v1/spygame/`. The owner is a group of 21-year-old guys: content must be fun, competitive and talk-driven, not "point at each other and giggle" decks (those were removed on purpose). See `README.md` for rules, structure and how to run it.

## Tech

Vanilla HTML/CSS/JS, no build step, no framework, no backend. Serve the folder statically (`start.bat`, port 3002). Installable PWA (`manifest.webmanifest`, `sw.js`), works offline after first load.

## Architecture

- Seating (in `app.js`): the player list order IS the seating order round the table; the "Bordplan" screen (`seats`) lets the group tap names in the order they sit. `App.holder()`/`setHolder()` track who has the phone (not persisted), `App.fromHolder()` returns the seats rotated to start there, and `App.ui.table(names, { cur, done, start, pick, empty, sm })` draws the oval table (seat 0 at the bottom, then clockwise). Imposter and Spygame reveal in that order, start the next round at the last revealer, and let the first pass screen re-pick the holder by tapping a seat. The owner asked for this after a 10-player night where the phone kept crossing the table.
- Drunk-proofing in `App.render` (added before the big test night, 2026-10-16): when the main button changes inside the same game (or the explosion screen appears), clicks are ignored for 500 ms (1200 ms on the explosion screen, so whoever grabs the phone does not start a new bomb by accident), because "Vis mit ord" and "Skjul og giv videre" sit in the same spot and a double tap used to flash a word away or show the next player's word. Every `.big` whose longest word has 10+ letters gets the class `fitw` and `--len`, which shrinks the font so the word stays on one line down to 320 px. The Spillere screen returns to the screen it was opened from (`playersBack`). After four drunk test personas played the night through (same day), every action that could throw away a round on one mistap now takes two taps: the vote (first tap marks the name, "Ud med X?", second tap votes), the back arrow mid-round in Imposter, Spygame and a ticking Bombe (`App.toast('Tryk igen ...')`, second tap within 2.5 s), and "Fjern alle" players. Bombe allows one "Ny kategori" per round (`B.swapped`), otherwise the holder could skip to an easy one. The imposter never starts the word round, and in Spygame a caught spy gets one guess at the word (phase `caught`), just like in Imposter. On iPhone `navigator.audioSession.type = 'playback'` in `ac()` makes the bomb audible in silent mode. The Spillere screen shows the list right under the input (the Bordplan card comes after it) so new names are visible above the keyboard.
- `app.js`: core (`App`). Navigation, player list, settings, `localStorage`, Web Audio sounds, vibration, wake lock, UI building blocks (`App.ui.shell/toggle/seg/stepper/range`), and `App.toast(msg)` for a short message at the top.
- `games/*.js`: one file per game. Each calls `App.register({ id, navn, kort, farve, render, onEnter, onLeave })` and registers button handlers with `App.on('name', fn)`. Buttons in HTML use `data-action="name"`; toggles use `data-change`, sliders `data-input`, forms `data-form`. Per-game settings persist via `App.gameSettings(id, defaults)`.
- `spotify.js` (`Spotify`): used only by Hitster. Authorization Code with PKCE (no secret; the public Client ID is in the file), token refresh, devices, play/pause via the Web API, and `findTrack` (searches title and artist, picks the original by album year, caches in `localStorage`). The app does not play audio itself, it remote-controls a Spotify Connect device. iOS suspends a paused Spotify app within minutes and the Connect device vanishes (the owner hit this: "det skal spille på Spotify, før man kan spille"), so inside a game Hitster never pauses: `hush()` in `games/hitster.js` plays a silent track (`Spotify.silence()` finds one by search and caches its URI in `localStorage`, falling back to a real pause) and `resumePlayback()` replays the song from the elapsed position; `pauseQuiet()` (a real pause) is only used when leaving Hitster. Spotify Development Mode (Feb 2026 rules): owner needs Premium, max 5 users, search `limit` max 10, batch endpoints gone, redirect URI must be `https://` or `http://127.0.0.1:PORT` (never `localhost`), so `start.bat` opens 127.0.0.1. `Spotify.blocked()` detects unusable origins. The login redirect returns to the page URL with `?code=`, handled in `games/hitster.js` on `DOMContentLoaded`; `sw.js` skips such requests. Hitster persists the running game in `localStorage` (`drukspil.hitster.run`) because the browser can be killed while the Spotify app is in front. In `games/hitster.js` the mode lives in `S.mode`/`H.mode` and the phases are `turn`, `place` (Klassisk), `judge` (Kasser), `clip` (Klip), `hl` (Streams; guess and result share the screen, `H.res` decides which), `reveal`, `win`/`end`. The Spotify Web API has no stream counts (and Development Mode dropped `popularity`), so `data/hitster-streams.js` is a generated snapshot in millions keyed by `'Titel|Kunstner'`; regenerate it with `node tools/update-streams.js` (kworb.net: first the global top 2500, then each artist's own page, found through the Spotify artist IDs cached in `tools/artist-ids.json`; kworb has no page for many smaller Danish acts, so about half the Danish songs have no number and are left out of Streams), never edit it by hand or fill in numbers from memory. Values under 100 million keep one decimal. Streams difficulty (`S.diff`: `let`, `mellem`, `svaer`) limits how far apart the two songs' counts may be (`BAND` in `drawChallenger`), and `S.htimer` gives an optional answer timer shown in the badge between the two cards. Countdown timers update the `.timer` element directly on each tick instead of re-rendering. Klip stops the song with a `setTimeout` after `Spotify.play` resolves, so real clip length depends on Spotify latency; `S.lag` (ms, "Justér klip") compensates, and the shortest clip is 0.5 s because Spotify Connect cannot do the 0.1 s the web games use. `playClip(from)` plays from a position and `armStop()` schedules the stop at the wall; pushing the wall while playing only re-arms the stop, pushing it while stopped resumes from `H.heard`. The bar and ring follow the song via `requestAnimationFrame` (`loop()`), and `paintWall()` moves the wall in place so the search keyboard stays open. The Klip screen is drawn once per clip step: while a clip plays only the play button and bar are repainted (`paintClip()`), and typing in the search only replaces the result list, so the phone keyboard never closes mid-search. The search covers every song in the data (not just the deck, so the list gives nothing away), and a guess counts when the normalised title matches (`norm()`), so a cover with the same title is fine. No "+" slot is shown between two timeline cards with the same year (the owner found it cluttered, and either side is correct).
- Bombe (`games/bombe.js`): the armed screen gets the classes `armed heat1..3` on `.screen` as the fuse burns (`heatClass(burnt())`, set on every tick in `flash()`), which CSS turns into faster sway, more smoke and a red glow; the boom screen builds its shards and embers with random inline `--x/--y/--dx/--dy` custom properties, and all explosion motion is CSS keyframes under `.screen.boom`. Role cards in Imposter and Spygame use `.reveal-box.same` (fixed min-height) so the imposter's card is the same size as a word card.
- `data/*.js`: all content. `hitster-songs.js` holds `['Titel', 'Kunstner', år]` rows (year = original release year, which is what the game scores on, not Spotify's album date). `HITSTER_SONGS_DK` (562 Danish songs, explicit ones included on purpose, chosen with `S.musik`: `alle`, `dk`, `int`; in `alle` the deck is balanced by `balance()` to as many Danish as international songs) was built by looking up each year in MusicBrainz, Deezer and iTunes and keeping a song only when two sources agreed; for old Danish music every single source is often wrong (reissue years, placeholder years), so never add years from memory or from one source. Imposter words are plain strings per category (600+ concrete nouns, each rated 1-5 for fun (sjov) and ease of hinting (nem) by five personas on 2026-10-11, scores in `tools/imposter-vurdering.json`; words under nem 3 or sjov 2.6, or rated 2 or lower by three of five, were removed, typical failures being too broad or dull everyday things (Stol, Dør, Gaffel), things the group does not know (Bridgerton, Lionel Richie, Lucky Luke) and near-duplicates (Pædagogmedhjælper next to Pædagog); rate new words the same way before adding them; modelled on the lists the popular Imposter apps use; the owner called the old abstract pairs "ubeskriveligt dårlige" and asked for lists from the internet rather than invented ones; keep Danish names and places to the most famous few, the owner found it "for meget dansk"), Bombe categories: `BOMBE_CATEGORIES` is an array of `{ tema, ord }` groups and `newPrompt()` in `games/bombe.js` never picks the same `tema` twice in a row, and a category that has been shown sleeps until the app is fully closed (the owner asked for this on 2026-10-16; the list `shown` lives in `sessionStorage` key `drukspil.bombe.vist`, which survives a reload but not a closed app). Each awake category has the same chance (picking a theme first made small themes run out first), a theme holding over half of the awake ones is taken first so the end of the list never forces one theme twice in a row, and only when all have been shown do the oldest wake up again while the 15 latest keep sleeping; the lists are copies of known category games, not inventions, plus byen/druk, and only a handful of Danish ones. Bombe has no adult categories at all (the owner took Frækt out on 2026-10-16), even with "Frækt indhold" on. On 2026-10-16 the owner went through the PDF of all categories and picked themselves: out went the everyday lists (Pålæg, Slik, Morgenmad, Sodavand, Noget på en pizza, Ting man kan grille, Ting i en kuffert, Ting i en bil, Ting på en strand, Tøj, Legetøj, Supermarkeder, Byer, Videospil, Sportsudstyr, Premier League-klubber, Øvelser i fitness, Actionfilm, Kendte) and all the Klassikere (Pigenavne, Drengenavne, Kropsdele, Jobs); in came their own Urmærker, Hovedstæder i verden, Amerikanske præsidenter, Michael Jackson-sange and Film med Mads Mikkelsen. So the group wants competitive "name as many as you can" lists with real, known answers over everyday-object lists, and the owner's own picks override the earlier rejections below (school-book and narrow lists were rejected when I chose them). Never add categories on my own; the owner adds them. Rejected by the owner: open or "creative" prompts ("Måder at...", "Ting man kan tage et shot af"), attribute lists that need thinking ("Ting der er klistrede", "Dyr der lægger æg"), narrow trivia ("Spillere der har vundet Ballon d'Or", "Film med Leonardo DiCaprio") and school-book lists (Hovedstæder). Speed is the fun; do not add anything that makes people pause. Spygame words per category in `spygame-words.js` (830, rated by the same five personas on 2026-10-12, scores in `tools/spygame-vurdering.json`, kept only with sjov 3+ and nem 3+; out went small Danish clubs, half-forgotten players, Danish drama series and odd "Måder at dø på"). Bombe categories were rated the same way (`tools/bombe-vurdering.json`): kept if sjov 3+ and nem 3+, or nem 4.2+ since speed is what makes Bombe fun; the persona Emil does not follow football, so do not cut football categories on his score alone. Imposter was tightened the same day to sjov 3+ (501 words). On 2026-10-16, the day before the big game night, four new personas (Jonas, Malthe, Victor, Rasmus) went through everything again and anything a single one of them flagged was cut, plus real duplicates (Fadøl next to Øl, Computerspil next to Videospil): now Imposter 448, Spygame 485, Bombe 61 (now 43 after the owner's own pass, see above). For Bombe the main reason was "man løber tør efter fem" (Cocktails, Is-smage, Streamingtjenester, Hunderacer) and attribute or think-first categories (Ting der kan eksplodere, Ting i en lufthavn). The few I first kept despite a flag (Ting man mister i byen, Sexstillinger, Ølbong, Rasmus Seebach) the owner also wanted out ("ja skal de"), so a flag means out, with no exceptions. On 2026-10-13 the owner called the remaining invented content "cringe" and "boomer-agtigt" ("Grunde til at skåle", the "Måder at dø på" quips) and asked that nothing be added that I think young people find cool. So the rule for all three games is: only real names and things; no invented situations ("Bestille en Uber til 300 meter"), stereotype jokes ("Lugt af Axe"), quips ("Pizza klokken 4") or slang an outsider thinks is youthful ("Fuckboy", "Netflix og chill", "Walk of shame"). The Spygame categories Byturen, Måder at dø på and Drengelejligheden were removed for that reason, and on 2026-10-16 Superkræfter ("for corny, det er sku kedeligt") together with the make-believe Spyfall places nobody has been to (Månen, Rumstationen, Ubåden, Nordpolen, Titanic): no fantasy or "what if" content. The persona reviews cannot catch this kind of cringe, because the personas are written by the same model that wrote the content (they gave "McDonald's klokken 4" 5/5), so never use them to justify keeping invented phrases. A full scan the same day widened the rule to anything that makes people think "hvorfor lige det?": specific places or situations with a twist (Ikeas kantine, Et solcenter), quirky picks included to be funny (Surströmming, Næbdyr, Ølstafet), old-fashioned or dad-like things and names (Romkugle, Petanque, Sigurd Barrett), home-made drinking stuff (Hjemmebrændt, Vodka-juice), children's things in adult categories (Flaskehalsen) and, for Bombe, attribute categories (Noget blødt). Only plain, famous, everyday names and things belong in the lists. Adult content lives in `adult: true` categories (Imposter, Spygame) and is only shown when the "Frækt indhold" toggle is on.
- `style.css`: chunky game look, mobile-first. The owner liked the Clash Royale-style buttons and cards but not the royal-blue diamond background, so the page is now deep plum (`--bg`) with a warm glow at the top, a blue glow at the bottom and faint bubble rings in several tile sizes; panels are indigo (`--panel`), bars use `rgba(var(--bar), a)`. Chunky buttons with dark outline and pressed bottom edge, display font Lilita One (self-hosted in `fonts/`) with text outline via the `--o-xs/--o-s/--o-l` text-shadow variables. Button colours are semantic (gold primary, blue secondary, green confirm, red remove); the game's own colour goes in `--accent` on `.screen`, its home tile and card frames. Cream "paper" cards (`.reveal-box`, `.deck-card`) use dark text. Entry animations only run when a tap re-renders (`#app.anim`), never on timer ticks; games can force them with `App.render(true)`.
- Icons are inline SVG, 64x64, dark `#0d1b3e` outline, drawn in code (no image files). Shared ones live in `App.icons`; each game passes its own as `ikon` to `App.register`. `App.ui.avatar(name, xl)` gives the coloured initial badge.

Load order in `index.html`: data files, `app.js`, `spotify.js`, then `games/*.js`, then `App.init()`.

## Conventions

- All user-facing text is Danish. Tone: playful party language, direct, short sentences. No em-dashes (use comma, colon or full stop). No emojis; use CSS or SVG for visuals.
- Keep play screens to one glance: big text, one primary button at the bottom, no scrolling mid-game.
- Drinks are phrased as "slurke" (sips) or "bunder"; keep penalties light and optional in spirit.
- When adding a game: new file in `games/`, register it (with an `ikon`), add it to `index.html` and to the precache list in `sw.js`.
- Privacy on pass-the-phone screens: the imposter's card must look identical in shape and colour to a normal word card from across the table; only the text differs.
- After editing JS/CSS: bump `?v=N` on every script/style tag in `index.html` and `CACHE`/`V` in `sw.js`, otherwise phones keep the old version.

## Testing

No test framework. Sanity-check with `node --check` on every JS file and click through the games in a mobile-sized browser (`.claude/launch.json` starts a local server on port 3002 for the in-app browser preview) (add players, run a full Imposter round, let a Bombe round explode, run a Spygame round). Hitster needs a real Spotify login that an agent must not do, so test it in the browser by faking Spotify: set `localStorage['drukspil.spotify.token']` to a non-expired fake token, then overwrite `Spotify.devices`, `.play`, `.pause`, `.findTrack` from the page console and play a round (the running game, including the hidden card, is readable in `localStorage['drukspil.hitster.run']`). Open the app on `http://127.0.0.1:3002`, not `localhost`. CSS animations in the browser pane only advance while the pane is visible (a screenshot makes it visible), so `getAnimations()` reporting `currentTime 0` is the test environment, not a bug.
